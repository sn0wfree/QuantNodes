# QuantNodes 系统架构设计文档

## 一、设计原则

### 1.1 核心设计理念

| 原则 | 说明 | 实现方式 |
|------|------|---------|
| **计算下推** | 尽可能将计算推送到数据库执行 | 表达式 → SQL 编译引擎 |
| **无感切换** | 研究员无需关心底层存储 | 统一 Factor 抽象层 |
| **渐进增强** | 新老代码可共存，逐步迁移 | Adapter 模式 + 接口兼容 |
| **AI 原生** | AI 能力不是插件而是核心 | 各层预留 AI 扩展点 |
| **可观测性** | 全链路可追踪可调试 | 日志、指标、追踪体系 |

### 1.2 非功能目标

| 目标 | 指标 |
|------|------|
| **性能** | 1000 万行因子计算 < 10 秒 |
| **易用性** | 新手 30 分钟可完成第一个策略回测 |
| **可扩展性** | 新增一种数据库引擎 < 100 行代码 |
| **可维护性** | 核心模块测试覆盖率 ≥ 80% |
| **稳定性** | 核心路径年故障率 < 0.1% |

## 三、核心模块详细设计

### 3.1 符号计算引擎 (Symbolic Engine)

#### 设计目标
- Python 表达式 → SQL 自动编译
- 多数据库引擎方言自适应
- 表达式静态类型检查
- 公共子表达式自动优化

#### 核心类设计

```python
# symbolic/parser.py
class Expression:
    """表达式基类，重载所有运算符"""
    def __add__(self, other): ...
    def __mul__(self, other): ...
    def __getattr__(self, name): ...
    def __call__(self, *args, **kwargs): ...

class Column(Expression):
    """列引用，如 F.close"""
    name: str

class FunctionCall(Expression):
    """函数调用，如 log(F.close)"""
    func: str
    args: List[Expression]

class WindowSpec:
    """窗口规范"""
    partition_by: Optional[List[str]]
    order_by: Optional[List[str]]
    rows: Optional[Tuple[int, int]]

# symbolic/compiler.py
class SQLCompiler:
    """SQL 编译器，访问者模式"""
    def visit(self, expr: Expression) -> str: ...
    def visit_Column(self, expr: Column) -> str: ...
    def visit_BinaryOp(self, expr: BinaryOp) -> str: ...
    def visit_FunctionCall(self, expr: FunctionCall) -> str: ...
    def visit_Window(self, expr: Window) -> str: ...

# symbolic/dialect.py
class Dialect(ABC):
    """数据库方言抽象"""
    @abstractmethod
    def compile_window(self, spec: WindowSpec) -> str: ...
    @abstractmethod
    def compile_function(self, func: str, args: List[str]) -> str: ...

class ClickHouseDialect(Dialect): ...
class DuckDBDialect(Dialect): ...
class MySQLDialect(Dialect): ...
```

#### 工作流程

```
用户输入: (F.close - F.open) / F.open * F.volume.rolling(20).mean()
        ↓
Parser 解析 → 表达式 AST 树
        ↓
TypeChecker 类型检查 → 验证列存在、类型兼容
        ↓
Optimizer 优化 → 公共子表达式提取、常量折叠
        ↓
Compiler 编译 → 基于 Dialect 生成对应 SQL
        ↓
Executor 执行 → 查询路由选择最优引擎执行
        ↓
结果 DataFrame
```

### 3.2 查询路由引擎 (Query Router)

#### 设计目标
- 根据查询特征自动选择最优引擎
- 统一多引擎访问接口
- 透明的引擎切换体验

#### 核心类设计

```python
# database/router.py
@dataclass
class QueryFeatures:
    """查询特征，用于路由决策"""
    estimated_rows: int  # 预估数据量
    has_window: bool     # 是否包含窗口函数
    has_join: bool       # 是否有 JOIN
    is_ad_hoc: bool      # 是否即席查询

class Router:
    """智能查询路由"""
    def __init__(self, engines: Dict[str, DatabaseEngine]):
        self.engines = engines
        self.performance_stats = {}  # 性能统计历史

    def route(self, query: Query) -> DatabaseEngine:
        """根据查询特征选择最优引擎"""
        features = self.extract_features(query)
        return self.decision_engine.decide(features)

    def execute(self, query: Query, engine: str = "auto") -> pd.DataFrame:
        if engine == "auto":
            engine = self.route(query)
        return engine.execute(query)

class DecisionEngine:
    """决策引擎，基于规则+统计"""
    def decide(self, features: QueryFeatures) -> str:
        # 规则 1: 大数量 + 窗口 = ClickHouse
        if features.estimated_rows > 1_000_000 and features.has_window:
            return "clickhouse"
        # 规则 2: 小数据 + 即席 = DuckDB
        if features.estimated_rows < 100_000 and features.is_ad_hoc:
            return "duckdb"
        # 规则 3: 元数据操作 = MySQL
        return "mysql"
```

### 3.3 回测引擎 (Backtest Engine)

#### 设计目标
- 向量化快速回测
- 完整的订单撮合逻辑
- 丰富的绩效指标输出
- 可扩展的风控钩子

#### 核心类设计

```python
# backtest/strategy.py
class Strategy(ABC):
    """策略基类"""
    def __init__(self, factors: List[Expression] = None):
        self.factors = factors  # 策略依赖的因子表达式

    @abstractmethod
    def on_bar(self, bar: Bar, position: Position) -> List[Order]:

    def on_stop(self, result: BacktestResult):

        self.orders = OrderBook()

    def submit_order(self, order: Order):
        self.orders.add(order)

    def match(self, bar: Bar) -> List[Trade]:
        """订单撮合，返回成交记录"""
        # 限价单、止损单、市价单撮合逻辑

# backtest/risk.py
class RiskRule(ABC):
    """风控规则，装饰器模式"""
    @abstractmethod
    def check(self, order: Order, broker: Broker) -> bool: ...

class MaxPositionSize(RiskRule):
    """最大持仓限制"""
    def __init__(self, max_size: float):

    """绩效指标集（40+ 指标）"""

    annual_return: float
    sharpe_ratio: float
    sortino_ratio: float
    max_drawdown: float
    calmar_ratio: float
    win_rate: float
    profit_factor: float

```

#### 回测数据流

```
行情数据 (OHLCV)
    ↓
[ 因子预计算 ] ← 符号表达式编译执行
    ↓
[ 策略 on_bar 循环 ] → 生成订单
    ↓
[ 风控检查 ] → 拦截不符合风控规则的订单
    ↓
[ 订单撮合 ] → 生成成交记录
    ↓
[ 持仓更新 ] → 计算持仓市值、盈亏
    ↓
[ 绩效计算 ] → 计算全部指标
    ↓
回测结果 Report → AI 分析与解读
```

## 五、设计模式应用

| 模式 | 应用场景 |
|------|---------|
| **访问者模式 (Visitor)** | SQL 编译器遍历表达式 AST |
| **策略模式 (Strategy)** | 数据库 Dialect 方言、路由决策规则 |
| **装饰器模式 (Decorator)** | 风控规则堆叠、缓存装饰器 |
| **抽象工厂 (Abstract Factory)** | LLM 客户端、数据库引擎创建 |
| **适配器模式 (Adapter)** | 兼容旧版 factor_table 接口 |
| **建造者模式 (Builder)** | 回测引擎、策略的复杂配置 |
| **观察者模式 (Observer)** | 订单成交事件、策略信号通知 |

## 七、关键技术决策汇总

| 决策 | 选型 | 理由 |
|------|------|------|
| **依赖管理** | Poetry | 现代标准，锁文件保证构建一致性 |
| **数据校验** | Pydantic 2.x | 类型安全、性能优秀、生态完善 |
| **SQL 抽象** | 自研编译器 | 最大化计算下推，ORM 表达能力不足 |
| **前端框架** | Streamlit | 极致简洁、研究员友好、开发效率高 |
| **可视化** | Plotly | 交互式图表，与 Streamlit 完美集成 |
| **测试框架** | pytest | 业界标准、插件生态丰富 |
| **AI 接口** | OpenAI Function Call | 结构化输出可靠，便于本地模型扩展 |
