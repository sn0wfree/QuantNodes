## 三、关键技术风险深度评估

### 风险 1：QuantStudio 依赖移除 🔴 高概率，中影响

**技术拆解**：
```
QuantStudio 依赖点:
├── __QS_Object__ 基类 → pydantic.BaseModel 替换
├── __QS_Error__ 异常 → 自定义异常体系
├── 工具函数 (~10 个) → 本地重写
└── Factor 运算类 → 参考接口完全重写
```

**缓解方案**：采用"接口兼容，实现重写"策略，trait → pydantic 1:1 映射
**最坏情况**：增加 2-3 天工期，不影响交付

---

### 风险 2：符号计算边缘 Case 🟡 中概率，低影响

**缓解方案**：
1. 第一期只实现核心 80% 功能（算术 + 窗口 + 常用函数）
2. 未覆盖场景优雅降级（fallback 到 pandas 计算）
3. 测试驱动开发，逐步扩展覆盖

**最坏情况**：部分复杂表达式回退 pandas，不影响核心功能

---

### 风险 3：SQL 方言适配复杂度 🟡 中概率，中影响

**缓解方案**：
1. 优先支持 ClickHouse（90% 使用场景）
2. SQLAlchemy Core 抽象层处理大部分方言差异
3. 差异点通过 Dialect 策略模式处理

**最坏情况**：初期只支持 ClickHouse，其他引擎后续迭代
