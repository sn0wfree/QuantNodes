# Per-Asset-Class Risk Model — 设计文档

## 1. 问题定义

**目标**: 对每类资产构建预警模型，回答：
> "未来 20 个交易日，该资产的波动率是否会进入历史高位？"

这不是择时（预测涨跌），而是风险评估（预测波动率环境）。

## 2. 目标变量 (y)

### 2.1 定义

```python
forward_vol = rets.rolling(20).std().shift(-20) * sqrt(252)
threshold = forward_vol.rolling(252).quantile(0.80)
y = 1 if forward_vol > threshold else 0
```

- **前向 20 日波动率**: 年化，与交易决策周期匹配
- **80% 分位数阈值**: 滚动 252 日窗口，点时间计算，无未来信息
- **正例含义**: "未来 20 天波动率处于近 1 年的高位"

### 2.2 为什么选这个 y

| 候选 y | 问题 | 结论 |
|--------|------|------|
| 前向收益 < -2% | 不可预测 (随机游走) | ❌ |
| 前向回撤 > 5% | 事件稀疏，< 10% 正例 | ❌ |
| 前向 maxDD > 2.5% OR return < 20%ile | 混合目标，含义不清 | ❌ |
| **前向波动率 > 80%ile** | **波动率聚集效应 (vol clustering) 是金融最稳健的统计规律** | **✅** |

### 2.3 正例率

| 资产 | 正例率 | 说明 |
|------|--------|------|
| 权益 (沪深300) | 16.7% | 约 1/6 时间处于高波动 |
| 商品 (金+豆粕+能源+有色) | 22.0% | 商品波动更频繁 |

## 3. 特征工程

### 3.1 特征分组

| 组 | 特征 | 数量 | 逻辑 |
|----|------|------|------|
| **自身技术** | ret_1d/5d/20d/60d/12m, vol_5d/20d/60d, skew_60d, kurt_60d, max_dd_60d, drawdown, dist_200ma | 13 | 资产自身的历史波动和趋势 |
| **VIX 恐慌** | vix, vix_zscore, vix_ratio_ma20/ma60, vix_above_20/25/30 | 7 | 全球风险偏好 |
| **宏观因子** | 8 v9 因子 + zscore + 1w 变化 | 24 | 增长/通胀/流动性/汇率 |
| **汇率** | dxy, dxy_zscore, dxy_logret | 3 | 美元强弱 (商品尤其敏感) |
| **利率** | real_rate, real_rate_zscore | 2 | 实际利率 (黄金的持有成本) |
| **市场结构** | gold_oil_corr, cn_us_spread, cn_us_spread_zscore | 3 | 风险偏好+中美利差 |
| **交互** | vix_x_ret_12m, vix_x_vol_20d, dxy_x_ret_20d | 3 | 非线性组合 |

**总计: 55 个原始特征**

### 3.2 特征选择

**方法**: 单信号 AUC 筛选 + 相关性去重

```
步骤 1: 计算每个特征与 y 的 AUC
步骤 2: 保留 AUC > 0.52 的特征
步骤 3: 去除相关性 > 0.95 的冗余特征
```

**注意**: 特征选择只在训练集上做，避免未来信息泄露。这是当前代码的 bug — 在全量数据上做选择。

### 3.3 为什么波动率特征是预测性的

波动率聚集 (volatility clustering) 是金融时间序列最稳健的统计规律：
- 高波动日往往跟着高波动日
- 模型用 `vol_20d` 预测前向波动率，本质是捕捉 vol clustering 的持续性
- 单信号 AUC 验证: `vix_zscore` 0.65, `vol_20d` 0.58

## 4. 模型选择

### 4.1 为什么选 LightGBM

| 模型 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| Logistic Regression | 可解释，简单 | 无法处理非线性 | ❌ 太简单 |
| Random Forest | 稳健，不易过拟合 | 对时间序列不友好 | ⚠️ 可做备选 |
| **LightGBM** | **速度快，处理缺失值，原生支持类别权重，叶节点生长** | **需要调参** | **✅** |
| XGBoost | 类似 LightGBM | 稍慢 | ⚠️ 备选 |
| LSTM/RNN | 理论上适合时间序列 | 数据量不够，调参复杂 | ❌ 8 年数据不够 |

### 4.2 超参数范围

| 参数 | 搜索范围 | 作用 |
|------|----------|------|
| num_leaves | [8, 64] | 树复杂度 |
| max_depth | [3, 8] | 树深度 |
| learning_rate | [0.01, 0.1] | 步长 |
| subsample | [0.6, 1.0] | 行采样防过拟合 |
| colsample_bytree | [0.6, 1.0] | 列采样防过拟合 |
| min_child_weight | [1, 10] | 叶子最小样本数 |
| reg_alpha | [1e-3, 10] | L1 正则化 |
| reg_lambda | [1e-3, 10] | L2 正则化 |
| scale_pos_weight | 自动计算 (负例/正例) | 类别不平衡 |

### 4.3 调参方法

**Optuna + 时间序列 CV**

```
不是用随机 CV 分割！
必须用时间序列顺序分割：
  Fold 1: train [0:500],  val [500:600]
  Fold 2: train [0:600],  val [600:700]
  Fold 3: train [0:700],  val [700:800]
  Fold 4: train [0:800],  val [800:900]
```

这是当前代码的第二个 bug — 用 `lgb.cv(nfold=4, stratified=True)` 做随机 CV，导致 CV AUC 虚高 (0.98)，但 walk-forward 很差 (0.40)。

## 5. 训练流程

### 5.1 Walk-forward 验证 (正确做法)

```
Fold 1: train 2018-01 ~ 2021-12, test 2022-01 ~ 2022-12
Fold 2: train 2018-01 ~ 2022-12, test 2023-01 ~ 2023-12
Fold 3: train 2018-01 ~ 2023-12, test 2024-01 ~ 2024-12
Fold 4: train 2018-01 ~ 2024-12, test 2025-01 ~ 2025-12
Fold 5: train 2018-01 ~ 2025-12, test 2026-01 ~ 2026-05
```

每个 fold：
1. 在训练集上做特征选择 (AUC 筛选)
2. 在训练集上用 Optuna + 时间序列 CV 调参
3. 用最优参数在训练集上训练最终模型
4. 在测试集上评估

### 5.2 校准 (Calibration)

使用 Platt scaling (sigmoid 校准) 将模型输出映射到概率空间：
- 原始输出: 未校准的分数 (0-1 但非概率)
- 校准后: 真实概率估计

### 5.3 评估指标

| 指标 | 用途 | 目标值 |
|------|------|--------|
| AUC | 排序能力 (整体) | > 0.65 |
| PR-AUC | 排序能力 (关注正例) | > 0.40 |
| Brier | 概率校准质量 | < 0.18 |

## 6. 已知问题

### 6.1 当前 WF AUC 低的原因

**根本原因: 训练期只有一种波动率 regime**

| 时期 | 权益波动率 | 市场状态 |
|------|-----------|----------|
| 2018-2020 | 中等 | 贸易战+疫情 |
| 2021 | **低** | 结构性牛市 |
| 2022 | **高** | 熊市 |
| 2023 | 中等 | 震荡 |
| 2024 | 低-中 | 震荡 |
| 2025-2026 | 中-高 | 分化 |

训练期 (2018-2021): 低波动为主
测试期 (2022): 高波动 (熊市)
→ 模型没见过"从低波动到高波动"的转换

### 6.2 修复方向

1. **时间序列 CV 替代随机 CV** — 修复 AUC 虚高
2. **特征选择仅在训练集内做** — 修复未来信息泄露
3. **移除"全 OOS 训练"步骤** — 该步骤是错误的设计
4. **增加滞后特征** — 让模型看到更长的波动率历史
