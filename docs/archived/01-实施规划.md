# QuantNodes AI 量化框架 - 实施规划

## 一、项目现状总览

| 维度 | 现状 | 重构后目标 |
|------|------|-----------|
| **代码规模** | ~9,800 行 | ~12,000 行（新增符号计算+AI模块） |
| **测试覆盖** | ~15% | ≥ 80% |
| **外部依赖** | QuantStudio (硬编码) | 无外部硬依赖 |

## 二、分阶段实施路线图

### 阶段 1：基础架构重构（7天）
> **目标**：移除 QuantStudio 依赖，建立独立可运行的核心

| 天数 | 任务 | 交付物 | 验收标准 |
|------|------|--------|----------|
| **Day 1** | 项目结构标准化 + Poetry 依赖管理 | `pyproject.toml`, 标准目录结构 | `poetry install` 成功 |
| **Day 2** | 基础对象模型重写（替代 __QS_Object__） | `core/base.py` | 异常体系、基类、工具函数 |
| **Day 3** | 配置系统重构（pydantic-settings） | `config/settings.py` | 支持环境变量、密钥管理 |
| **Day 4** | 数据库连接层重写（MySQL + ClickHouse） | `database/` 模块 | 连接池、SQL执行、类型安全 |
| **Day 5** | DuckDB 引擎集成 + 查询路由 | `database/router.py` | 多引擎自动路由选择 |
| **Day 6** | factor_table 模块重构（移除 ClickSQL 依赖） | `factor/table.py` | 兼容原接口，可运行测试 |
| **Day 7** | 阶段一测试 + 文档 | 单元测试, README | 所有测试通过, 可独立运行 |

**风险点**：
- ⚠️ factor_table 对 ClickSQL 的依赖深度需要仔细拆解
- ✅ 缓解策略：保留原接口不变，内部替换实现

---

### 阶段 2：符号计算引擎（8天）
> **目标**：实现 Python 表达式 → SQL 编译核心能力

| 天数 | 任务 | 交付物 | 验收标准 |
|------|------|--------|----------|
| **Day 8** | SymPy 表达式解析器 + AST 构建 | `symbolic/parser.py` | 解析 `F.close - F.open` 生成 AST |
| **Day 9** | 类型推导系统 + 静态检查 | `symbolic/typecheck.py` | 检测列不存在、类型不匹配 |
| **Day 10** | SQL 编译器核心（ClickHouse 方言） | `symbolic/compiler.py` | 编译基础算术表达式为 SQL |
| **Day 11** | 窗口函数支持（rolling, rank 等） | `symbolic/window.py` | 支持 `F.volume.rolling(20).mean()` |
| **Day 12** | 技术指标函数库（第一期 30+ 指标） | `symbolic/functions.py` | MA, RSI, MACD, BOLL 等 |
| **Day 13** | AST 优化器（公共子表达式提取） | `symbolic/optimizer.py` | 优化后 SQL 性能提升 ≥ 30% |
| **Day 14** | 执行引擎集成 + 查询路由 | `symbolic/executor.py` | 一键编译执行，自动选库 |
| **Day 15** | 符号计算引擎测试 + 文档 | 单元测试, 示例 notebook | 50+ 测试用例全部通过 |

**里程碑**：
```python
# 必须通过此验收测试
from QuantNodes.symbolic import F

expr = (F.close - F.open) / F.open * F.volume.rolling(20).rank()
result = expr.execute(engine="clickhouse")
assert isinstance(result, pd.DataFrame)  # ✓
```

## 三、关键技术决策记录

| 决策项 | 选择 | 理由 |
|--------|------|------|
| **包管理器** | Poetry | 现代标准，支持 lock 文件 |
| **配置管理** | pydantic-settings | 类型安全，支持多源配置 |
| **数据库抽象** | SQLAlchemy Core | 统一 SQL 方言，多引擎支持 |
| **符号计算** | SymPy | 成熟的符号计算库，AST 处理完善 |
| **Web 框架** | Streamlit | 极致简洁，研究员友好 |
| **可视化** | Plotly | 交互式图表，与 Streamlit 完美集成 |
| **测试** | pytest + pytest-cov | 业界标准 |
| **代码规范** | Black + Ruff | 快速、现代 |
| **日志** | structlog | 结构化日志 |

## 四、风险与应对

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|----------|
| QuantStudio 依赖移除超预期 | 🔴 高 | 工期延误 2-3 天 | 采用"接口兼容，重写实现"策略，保留原 API 不变 |
| 符号编译边缘 case 多 | 🟡 中 | 功能不完善 | 先实现核心 80% 功能，剩余 20% 迭代补充 |
| SQL 方言适配复杂 | 🟡 中 | 多引擎支持延迟 | 优先搞定 ClickHouse，DuckDB 和 MySQL 后续迭代 |
| AI 提示工程效果不稳定 | 🟡 中 | 用户体验差 | 建立提示词版本管理 + 备选方案（模板填充） |
