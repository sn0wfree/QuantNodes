## 三、关键设计决策

### 3.1 两层列名设计

**问题**: `date_column` 和 `code_column` 原本同时用于 SQL `ORDER BY`（需要数据库原始名）和 executor 过滤（需要映射后名字），当 `column_mapping` 非空时产生冲突。

**方案**: 拆分为两层：

```yaml
data:
  # 数据库层（用于 SQL 查询）
  db_date_column: trade_date
  db_code_column: ts_code
  
  # 内部标准层（用于 executor/backtest）
  date_column: date
  code_column: code
  
  # 映射关系
  column_mapping:
    ts_code: code
    trade_date: date
    vol: volume
```

**流转路径**:
```
SQL ORDER BY ts_code, trade_date     ← 使用 db_* 字段
       ↓
DataFrame: [ts_code, trade_date, close, vol]
       ↓ column_mapping
DataFrame: [code, date, close, volume]   ← 内部标准名
       ↓ _normalize_columns
DataFrame: [Code, date, Close, Volume]   ← 回测引擎 PascalCase
```

### 3.2 standard_columns 预定义

通过 YAML 配置文件预先设定标准列名映射：

```yaml
data:
  standard_columns:
    open: open
    high: high
    low: low
    close: close
    volume: volume
```

### 3.3 日期类型兼容

executor 日期筛选兼容 String 和 Date 两种类型：
- CSV 数据：`date` 列为 String，需要 `.str.to_date()`
- ClickHouse 数据：`date` 列已转换为 Date 类型，直接比较

## 八、数据流全链路图

```
┌─────────────────────────────────────────────────────────┐
│  YAML 配置                                               │
│  data.source: clickhouse                                 │
│  data.db_date_column: trade_date  ← 数据库原始名          │
│  data.db_code_column: ts_code     ← 数据库原始名          │
│  data.date_column: date           ← 内部标准名            │
│  data.code_column: code           ← 内部标准名            │
│  data.column_mapping: {ts_code: code, trade_date: date}  │
└─────────────────────┬───────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────────────┐
│  _build_query()                                          │
│  SELECT ts_code, trade_date, open, high, low, close, vol │
│  FROM quote.cn_stock                                     │
│  WHERE trade_date >= toDateTime('2023-07-01')            │
│  ORDER BY ts_code, trade_date        ← 使用 db_* 字段    │
└─────────────────────┬───────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────────────┐
│  ClickHouse / MySQL / SQLite / DuckDB / CSV / Parquet    │
│  返回 DataFrame: [ts_code, trade_date, open, ...]        │
└─────────────────────┬───────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────────────┐
│  column_mapping 应用                                     │
│  df.rename({ts_code: code, trade_date: date, vol: volume})│
│  DataFrame: [code, date, open, high, low, close, volume] │
└─────────────────────┬───────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────────────┐
│  DateTime → Date 类型转换                                 │
│  使用 date_column ("date") 查找列，转换 Datetime → Date   │
└─────────────────────┬───────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────────────┐
│  ConfigExecutor                                          │
│  - 解析因子表达式 (ExprParser)                             │
│  - 执行运算 (with_columns 逐层添加)                       │
│  - 日期筛选 (兼容 String/Date 类型)                       │
│  - 股票筛选 (使用 code_column，兼容 PascalCase fallback)  │
│  - 生成信号 (signal 列)                                   │
└─────────────────────┬───────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────────────┐
│  ConfigBacktestRunner._normalize_columns()               │
│  code → Code, close → Close, open → Open                 │
│  (date 保持小写)                                          │
└─────────────────────┬───────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────────────┐
│  回测引擎                                                │
│  ConfigStrategyNode → ExecutionBrokerNode → BacktestResult│
│  期望列名: Code, Close, Open, date, signal               │
└─────────────────────────────────────────────────────────┘
```

## 九、待讨论 / 后续工作

### 9.1 已知限制

1. **嵌套表达式**: `close * volume` 或 `ts_sum(close * volume, 5)` 无法直接解析，需拆分为中间因子
2. **ClickHouse 查询性能**: HTTP 接口全量查询 44s，建议用 `query_filter` 缩小范围
3. **LLMWikiFy**: Wiki 搜索/报告生成功能是外部依赖，本轮未涉及

### 9.2 可能的优化方向

1. **ClickHouse Native 接口**: 替换 HTTP 接口，预期查询性能提升 3-5x
2. **增量数据加载**: 缓存已查询的数据，避免重复查询
3. **并行策略执行**: 多个策略可并行运行
4. **策略参数网格搜索**: 在 YAML 中支持参数扫描
5. **回测结果持久化**: 自动保存到 ClickHouse 或 Parquet 文件

### 9.3 后续核心功能

- **功能2**: 策略监控与优化（调度层、监控层、版本管理层）
- **功能3**: 研报复现（PDF 解析、因子自动提取、因子库管理）
