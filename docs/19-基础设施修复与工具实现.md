## 一、问题背景

基于设计文档（13-Agent系统架构设计、15-Config-Driven方案）与当前代码的对比审查，发现以下关键问题：

### 1.1 已完成部分

| 阶段 | 状态 | 说明 |
|------|------|------|
| Phase 1: 核心框架 | ✅ 已完成 | 7 个核心模块、16 个测试文件全部就绪 |
| Phase 2: 工具骨架 | ⚠️ 部分完成 | 6 个工具文件存在，但 4 个是占位符 |
| Config 系统 | ⚠️ 部分实现 | ConfigLoader/ConfigExecutor 可用，但注册表脱节 |

### 1.2 待修复问题

| 问题 | 严重度 | 影响 |
|------|--------|------|
| **双注册表脱节** | 🔴 高 | config/loader.py 有 30 个静态假注册条目，factor_functions.py 有 137 个真实算子，两者完全不互通 |
| **config 位置错误** | 🟡 中 | 设计文档要求 agent/config/，实际在 QuantNodes/config/，agent 工具无法直接导入 |
| **4 个工具是占位符** | 🔴 高 | BacktestTool、StrategyTool、FactorTool、PipelineTool 返回 stub 数据 |
| **命名不一致** | 🟡 中 | config 中声明的 weighted_avg/blend/percentile 在 factor_functions 中不存在 |

---

## 二、修复策略

### 核心原则

1. **单一数据源**：删除假注册表，复用 factor_functions 的真实注册表
2. **位置统一**：config 移到 agent/config/，与 agent 工具直接关联
3. **渐进实现**：先修基础设施，再做工具实现

### 四阶段实施路径

```
阶段 A: 统一注册表 (0.5天)
    ↓
阶段 B: 移动 config (0.5天)
    ↓
阶段 C: 实现工具 (2天)
    ↓
阶段 D: 测试验证 (0.5天)
```

## 三、修复实施

### 阶段 A：统一注册表

**修改 `config/loader.py`**：

删除 L247-283 的 `_OPERATOR_REGISTRY` 假注册表（30 个静态条目），新增：
```python
from QuantNodes.factor_node.factor_functions import list_operators as _list_operators

def _get_operator_registry():
    return {op["name"]: op for op in _list_operators()}
```

**结果**: 从 30 个静态算子 → 137 个真实算子

### 阶段 B：Config 目录迁移

**迁移**: `QuantNodes/config/` → `QuantNodes/agent/config/`

**文件列表**:
- `__init__.py`
- `types.py` - 配置类型定义
- `loader.py` - 配置加载器
- `executor.py` - 配置执行器
- `templates/` - 模板目录

**修复导入**:
```python
# 之前 (executor.py):
from ..operators import SectionOperators

# 现在:
from QuantNodes.operators import SectionOperators
```

### 阶段 C：实现 4 个工具

#### BacktestTool（回测工具）

从占位符升级为真实实现：
1. 使用 CodeSandbox 安全执行代码
2. 从 namespace 提取 StrategyNode / RiskNode / BrokerNode
3. 手动串联 strategy.execute() → risk.execute() → broker.execute()
4. 返回真实回测结果

**参数**:
- `pipeline_code` (string, required): 策略 Pipeline 代码
- `start_date` (string, required): 回测开始日期 YYYY-MM-DD
- `end_date` (string, required): 回测结束日期 YYYY-MM-DD
- `initial_cash` (number, optional): 初始资金，默认 100000

#### StrategyTool（策略生成工具）

仍为占位符，需要 LLM 集成。返回提示信息："需要配置 LLM 客户端"

#### FactorTool（因子分析工具）

从占位符升级为真实实现：
1. 使用 CodeSandbox 安全执行因子代码
2. 要求代码创建 result 变量 (Polars DataFrame)
3. 计算 IC 分析 (ic_mean, ic_std, icir, rank_ic_mean)
4. 计算相关性分析

**代码要求**:
```python
import polars as pl

result = pl.DataFrame({
    "date": ["2024-01-01", ...],
    "code": ["A", ...],
    "factor_value": [0.1, ...],
    "forward_return": [0.05, ...],
})
```

#### PipelineTool（Pipeline 验证工具）

增强验证：语法检查 + 安全检查 (CodeSandbox) + 节点信息提取
