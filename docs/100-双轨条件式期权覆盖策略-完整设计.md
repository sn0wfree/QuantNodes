## 一、背景与动机

### 1.1 纯 Put 对冲的失败 (docs/99 §3.6)

A/B 实验结论 (2023-2025, 727 天, hedge_ratio=0.10):

| 模式 | Sharpe | 成本/年 | 结论 |
|------|--------|--------|------|
| baseline (无对冲) | 1.209 | — | 基线 |
| none (总是买裸 Put) | 0.861 | -4.98% | 净拖累 -28.7% |
| both (双择时 min) | 1.147 | -1.76% | 最优但仍拖累 |

**核心问题**: 纯买方策略在商品市场上**必然**是净成本——商品 VRP 偶发性 (文献 5),
权利金持续消耗 > 尾部保护收益.

### 1.2 设计目标

设计一个**自融资或正 carry** 的期权覆盖策略:
1. **尾部保护**: 极端下跌时提供对冲, 限制最大回撤
2. **成本摊平**: 平时通过卖方/套利/趋势策略产生收入, 抵消保护成本
3. **非纯买方**: 利用 VRP (IV − HV) 的时变特性, 高 VRP 时卖, 低 VRP 时买

### 1.3 关键数据发现: VRP 品种分化

商品期权 VRP (IV − HV_20) 均值按品种分布:

**VRP 正 (适合卖 vol)** — IV 系统性高于 HV, 卖方有正期望:

| 品种 | mean_VRP | VRP>0 占比 | VRP>5% 占比 | 说明 |
|------|----------|-----------|------------|------|
| PD | +0.348 | 98% | — | 新品种, 样本小 |
| FU | +0.087 | 100% | — | 燃油, 结构性 VRP |
| AU | +0.032 | 76% | 26.9% | 黄金, 经典正 VRP |
| L | +0.056 | 65% | 26.4% | 塑料 |
| PP | +0.048 | 66% | 27.5% | 聚丙烯 |
| RU | +0.013 | 52% | 22.9% | 橡胶 |
| CU | +0.009 | — | 10.0% | 铜 |

**VRP 负 (适合买保护)** — IV 系统性低于 HV, 买方有正期望:

| 品种 | mean_VRP | VRP>0 占比 | 说明 |
|------|----------|-----------|------|
| JD | -0.058 | 48% | 鸡蛋, 高波动农产品 |
| FG | -0.041 | 43% | 玻璃 |
| I | -0.041 | 40% | 铁矿石 |
| SA | -0.027 | 50% | 纯碱 |
| M | -0.018 | 45% | 豆粕 |

**策略含义**: 不同品种 VRP 方向相反, 不能统一策略.
VRP 正品种适合卖方收入, VRP 负品种适合买方保护.

## 二、策略架构

### 2.1 总体结构: 品种分层 + 双轨覆盖

```
                    ┌── VRP 正品种 (AU/L/PP/RU/CU/FU...)
                    │   Track A (Put Spread 保护, 轻仓)
  品种分类 ─────────┤   Track B (卖 Put Spread 收入, 重仓)
  (VRP 信号)        │   → 净 carry 为正
                    │
                    └── VRP 负品种 (I/M/FG/SA/JD...)
                        Track A (Put Spread 保护, 标准仓)
                        Track B: 不开启
                        → 纯保护, 但成本被 Track B 正品种收入对冲
```

### 2.2 双轨定义

**Track A — 尾部保护 (Put Spread, always on)**

所有品种始终持有 Put Spread 作为基础保护:
```
买 0.25Δ Put  +  卖 0.10Δ Put
净成本 ≈ 裸 Put 的 40% ~ 50%
保护区间: 标的下跌 ~5% 到 ~15% (0.10Δ 行权价处封顶)
最大净支出: 净权利金
```

**Track B — 收入增强 (条件式, regime-switching)**

仅在满足条件时开仓, 产生权利金收入. **三种收入策略需 A/B 对比** (见 §五).

### 2.3 Regime 切换 (市场状态 → 策略行为)

| 状态 | 定义 | Track A | Track B |
|------|------|---------|---------|
| 平静 | VRP 高 + Contango + IV 中位 | 轻仓保护 | **重仓卖** (VRP 正品种) |
| 正常 | VRP 中性 + 结构中性 | 标准保护 | 不动 |
| 压力 | VRP 低/负 + Backwardation | 标准保护 | 已平仓 (信号反转) |
| 尾部 | 暴跌 | **获利激活** | 已平仓 |

**Regime 评分 (fragility_score)**:

```
fragility = 0.4 × IV_percentile           (IV 越高越脆弱)
          + 0.3 × basis_percentile         (Backwardation 越深越脆弱)
          + 0.3 × (1 − VRP_percentile)    (VRP 越低越脆弱)

fragility > 0.6: 压力/尾部 → Track A 加重, Track B 关闭
fragility 0.3~0.6: 正常 → 标准
fragility < 0.3: 平静 → Track A 轻仓, Track B 开启 (VRP 正品种)
```

## 三、Track A: 尾部保护 (Put Spread)

### 3.1 合约选择

```python
def select_put_spread(
    product: str,
    trade_date: str,
    underlying_price: float,
    buy_delta: float = 0.25,    # 多腿: 0.25Δ 虚值 Put
    sell_delta: float = 0.10,   # 空腿: 0.10Δ 更虚值 Put
    min_days: int = 30,
    max_days: int = 60,
) -> tuple[OptionSelection, OptionSelection] | None:
    """选 Put Spread: 多 0.25Δ + 空 0.10Δ (同到期月).

    返回 (long_put, short_put) 或 None.
    long_put.strike > short_put.strike (均 < underlying).
    """
```

**选择逻辑**:
1. 筛选同到期月的 Put 合约 (30-60 天窗口)
2. long_leg: `|delta - (-0.25)|` 最小
3. short_leg: `|delta - (-0.10)|` 最小
4. 确保 `long_leg.strike > short_leg.strike` (否则跳过)

### 3.2 仓位与成本

```
保护名义 = net_qty × hedge_ratio × price × multiplier
手数 = 保护名义 / (|long_delta| × price × multiplier)
      ≈ net_qty × hedge_ratio / |long_delta|

成本/年 (估算):
  裸 Put:   ~5% NAV (hedge_ratio=0.10, A/B 实测)
  Put Spread: ~2-2.5% NAV (卖腿回收 ~50-60%)
```

### 3.3 择时 (fragility_score 调节)

- `fragility < 0.3` (平静): hedge_ratio × 0.5 (轻仓, 平时不需重保)
- `fragility 0.3~0.6` (正常): hedge_ratio × 1.0
- `fragility > 0.6` (压力): hedge_ratio × 1.5 (加重保护)

### 3.4 展期与到期

- 到期前 `roll_days` (7 天) 滚动到下一合约
- 到期结算: long_put 内在价值 = max(K_long − S, 0); short_put 赔付 = max(K_short − S, 0)
- 净结算 = max(K_long − S, 0) − max(K_short − S, 0), 为正 (保护区间内)

### 3.5 Phase 3 A/B 结果 (2023-2025, 727 天, hedge_ratio=0.25)

| 策略 | Sharpe | AnnRet | MaxDD | 最差单日 | 成本/年 |
|------|--------|--------|-------|---------|--------|
| **baseline** | 1.209 | 0.140 | -0.111 | -4.88% | — |
| naked_put | 0.408 | 0.088 | -0.088 | -5.64% | -13.54% |
| **put_spread** | **0.472** | **0.104** | **-0.089** | -6.76% | **-8.47%** |

**结论**:
- Put Spread 成本降低 37% (−8.47% vs −13.54%), 验证 Track A 有效
- 但 Sharpe 仍低于基线, 单独不足以翻转正 carry
- MaxDD 改善有限 (−0.089 vs −0.111), 尾部保护有效但不显著
- **需要 Track B 收入策略覆盖剩余 −8.47%/年成本**

## 四、品种分层

### 4.1 VRP 品种分类

**分类标准**: 历史 VRP 均值 + VRP>0 天数占比

| 分类 | 标准 | 品种 (示例) | 策略行为 |
|------|------|------------|---------|
| **VRP 正** | mean_VRP > +0.01 且 VRP>0 占比 > 55% | AU, L, PP, RU, FU, CU, V | 双轨: Track A + Track B |
| **VRP 中性** | mean_VRP ∈ [−0.01, +0.01] | SR, MA, TA | 仅 Track A |
| **VRP 负** | mean_VRP < −0.01 或 VRP>0 占比 < 45% | I, M, FG, SA, JD, B | 仅 Track A (买入便宜) |

**动态分类**: VRP 品种分类基于滚动 252 天窗口计算, 允许品种随时间切换类别.

### 4.2 VRP 面板构建

```sql
-- vrp_daily: 逐品种逐日 VRP + 分位
CREATE TABLE vrp_daily AS
SELECT
    iv.product,
    iv.trade_date,
    iv.atm_iv,
    hv.hv_20,
    iv.atm_iv - hv.hv_20 AS vrp,
    iv.iv_percentile,
    -- VRP rolling 252 天分位
    ...
FROM option_iv_daily iv
JOIN volatility_hv_daily hv
  ON iv.product = hv.product AND iv.trade_date = hv.trade_date;
```

## 五、Track B: 收入增强 — 三种策略 A/B 对比

用户确认: **三种收入策略 + 裸买基线** 全部实现对比.

### 5.1 策略 B1: 卖 Put Spread (VRP 条件式收割)

```
触发条件 (三者同时满足, 仅 VRP 正品种):
  ① VRP 分位 > 70%     (IV 显著高于 HV, 权利金贵)
  ② IV 分位 > 50%      (波动率偏高, 卖方有利)
  ③ basis 分位 < 40%   (Contango, 市场安全, 下跌概率低)

动作: 卖 0.15Δ Put  +  买 0.05Δ Put  (defined risk)
  K_sell (0.15Δ) > K_buy (0.05Δ), 均远低于标的价
  净收入 = P(0.15Δ) − P(0.05Δ)

风控:
  最大亏损 = (K_sell − K_buy) × mult × qty  (有界)
  Delta 敞口 = |sell_delta − buy_delta| × qty (做多 delta, 需对冲)
  → Delta 对冲: 调整 CTA 期货仓位或额外卖空期货

退出:
  VRP 分位 < 30%  → 平仓获利 (IV 回落, 权利金缩水)
  或持有至到期     → 结算 (大概率 OTM, 全额收入)
```

**预期收益**: AU/L/PP/RU 约 23-27% 交易日触发, 预期 +2~4%/年.
**风险**: 尾部事件时 Put Spread 亏损, 但 Track A 的保护可部分对冲.

### 5.2 策略 B2: Covered Call (备兑看涨)

```
触发条件: CTA 净多头品种 (qty > 0), 任何 VRP 状态
动作: 卖 0.30Δ Call (同一品种同一到期月)
  权利金收入 = C(qty_call × premium × mult)

效果:
  + 权利金收入抵消 Track A 成本
  − 标的涨超 Call 行权价时, CTA 上行被截断
  Delta 敞口降低 (Call 正 delta 抵消期货多头)

退出:
  到期: 标的 < K_call → 全额收入; 标的 > K_call → 交货 (CTA 多头被对冲)
  展期: 到期前 roll_days 滚动
```

**适用性**: 所有品种 (不依赖 VRP 方向), 但封顶 CTA 趋势上行收益.
**与文献 2 的张力**: CTA 趋势策略的凸性来自上行无封顶, Covered Call 会削弱这一凸性.

### 5.3 策略 B3: Calendar Spread (日历价差)

```
触发条件:
  IV 期限结构 Contango (近月 IV < 远月 IV) + VRP 正

动作: 卖近月 ATM Put  +  买远月 ATM Put (同 strike, 不同到期)
  近月 theta 衰减快 → 权利金缩水快 → 获利
  远月 theta 衰减慢 → 持有价值

效果:
  + 近月时间价值加速归零, 远月保持
  + 不依赖方向, 纯 theta 差套利
  − 需要 IV 期限结构数据 (近月 vs 远月 IV)
  − 展期复杂 (近月到期后需滚动远月)

退出:
  近月到期 → 结算 (OTM 则全额近月收入)
  远月可平仓或转为 Track A 保护腿
```

**适用性**: 仅 IV 期限结构 Contango 的品种.
**数据需求**: 需要近月/远月 IV 分别计算 (当前 IV 面板仅 ATM 近月).

### 5.4 基线: 裸买 Put (docs/99 已测)

```
动作: 买 0.25Δ Put (naked)
成本: ~5%/年 (hedge_ratio=0.10, A/B 实测)
作用: 对照基线, 验证其他策略的改善幅度
```

### 5.5 A/B 矩阵

| 策略 | 收入来源 | 方向依赖 | 封顶风险 | VRP 依赖 | 工程复杂度 |
|------|---------|---------|---------|---------|-----------|
| 裸买 Put (基线) | 无 | 无 | 无 | 无 | 已实现 |
| Track A: Put Spread | 成本降低 50% | 无 | 保护有界 | 弱 | 低 |
| B1: 卖 Put Spread | 权利金 | 对冲 delta | 有界 | 强 | 高 (需 broker_sell) |
| B2: Covered Call | 权利金 | CTA 多头 | **封顶上行** | 弱 | 中 (需 broker_sell) |
| B3: Calendar | theta 差 | 无 | 展期风险 | 中 | 高 (需期限结构) |

## 六、基础设施需求

### 6.1 CtaBroker 扩展: option_sell 支持 (关键)

当前 broker 仅支持 `option_buy` (买方). 需新增 `option_sell`:

```python
class Position:
    kind: str = "future"  # "future" | "option_buy" | "option_sell"  ← 新增
```

**卖方会计**:
```python
def _place_option_sell_order(...):
    # 开仓 (卖出期权):
    #   cash += qty × premium × mult   (权利金收入)
    #   margin_deposit = max_loss_spread × mult × qty  (Put Spread: 有界)
    #                   或 SPAN 简化: strike × margin_ratio × mult × qty (裸卖)
    #   cash -= margin_deposit

    # 平仓 (买回):
    #   cash -= qty × current_premium × mult  (买回成本)
    #   cash += margin_deposit (释放)

    # 到期结算:
    #   Put: cash -= max(K − S, 0) × mult × qty  (赔付买方)
    #   Call: cash -= max(S − K, 0) × mult × qty
    #   margin_release
```

**Put Spread 保证金**:
```python
margin = (K_short − K_long) × mult × qty  # defined risk
```

**工作量评估**: 中大. 需修改:
- `Position` 加 `kind="option_sell"`
- `_place_option_sell_order()` 新方法
- `equity()` 加卖方浮动盈亏
- `_expire_options()` 加卖方赔付
- `margin_used()` 加卖方保证金

## 八、风险管理与边界

### 8.1 风险清单

| 风险 | 影响 | 缓解 |
|------|------|------|
| 卖 Put Spread 尾部亏损 | Track B 大幅亏损 | 单品种仓位上限 2% NAV; Track A 对冲 |
| Covered Call 封顶 CTA 上行 | 趋势行情踏空 | 仅在非趋势品种使用; Call delta 可调 |
| VRP 信号误判 | 卖在 IV 低点 | 多条件确认 (VRP + IV + basis); 止损 |
| 流动性风险 | 平仓滑点 | 仅交易 OI > 1000 的合约; 日内不调仓 |
| 保证金不足 | 强平 | margin_call=True; 仓位上限 15% NAV |
| 到期日数据推断错误 | 结算异常 | 与交易日历校验; 异常时按内在价值兜底 |

### 8.2 仓位约束

```
单品种 Track A 名义 ≤ 5% NAV
单品种 Track B 名义 ≤ 3% NAV
全组合期权保证金占用 ≤ 15% NAV
全组合期权买方成本 ≤ 3% NAV/年
全组合期权卖方收入 ≥ 2% NAV/年 (Track B 开启时)
```

### 8.3 回测边界

1. **2022 前期权未上市**: 部分品种 RB 2022-12 起, 2022 前对冲覆盖不全, 需注明
2. **卖方假设**: 回测假设可按收盘价成交, 实际有买卖价差
3. **保证金模型简化**: Put Spread 按有界风险计, 实际交易所可能更高
4. **IV 反解精度**: 低流动性合约 IV 可能不准, 已过滤 OI > 0

- 若 Calendar Spread 数据不可用: 放弃 B3, 对比 A + B1 + B2

## 六、Regime-Adaptive 策略回测结果

### 6.1 策略逻辑

基于 期权工作平台 v3 Regime switching 研究, 根据 IV 分位 + HV/IV 路由不同期权策略:

| Regime | 条件 | 路由策略 |
|--------|------|---------|
| LOW_VOL_NO_DROP | IV分位<0.5, HV≤IV | 卖 Put Spread (收 theta) |
| LOW_VOL_DROP | IV分位<0.5, HV>IV | 买 Put Spread (保护) |
| HIGH_VOL_NO_DROP | IV分位≥0.5, HV≤IV | 卖 Strangle (高 IV 收取) |
| HIGH_VOL_DROP | IV分位≥0.5, HV>IV | 买 Long Put (对冲) |

参数: iv_pct_window=20, hv_window=20, 持仓20天或regime变化时平仓

### 6.2 回测结果 (2023-2025, 3年)

| 品种 | NAV | 收益 | 交易次数 | 结论 |
|------|-----|------|---------|------|
| RB | 1.004 | +0.4% | 371 | 微正, regime 信号有效 |
| I | 0.974 | −2.6% | 379 | 亏损, 波动大保护不足 |
| AG | 0.957 | −4.3% | 336 | 亏损, 需调参 |

### 6.3 Regime 分布 (前100天采样)

| 品种 | LOW_VOL_NO_DROP | LOW_VOL_DROP | HIGH_VOL_NO_DROP | HIGH_VOL_DROP |
|------|----------------|-------------|-----------------|-------------|
| RB | 19% | 37% | 36% | 8% |
| I | 8% | 44% | 27% | 21% |
| AG | 31% | 26% | 38% | 5% |

### 6.4 待优化

1. **品种调参**: 不同品种的 iv_pct_high/hv_threshold 应独立优化
2. **持仓期**: 20天固定持仓可能不是最优, 可改为 regime 变化时才平仓
3. **组合对冲**: 接入 DeltaHedgeManager 做 futures delta 对冲
4. **P&L 分解**: 接入 PnlDecomposer 跟踪 theta/gamma/vega 各分量
