## 当日教训

### L-20260708-1: 协方差估计在低维场景下价值有限 [MEDIUM]

**问题**：Stage 11 引入 covariance estimation + risk parity，结论是"技术 OK，表现不佳"。

**根因**：本阶段因子数量 5-6 只（早期 V1.0/V2 时期），低维场景下：
- 协方差矩阵估计噪声大（5x5 矩阵需要至少 60 个独立样本才稳定）
- RP（Risk Parity）等于"等波动贡献"，对低相关组合是天然解
- 在已经使用逆波动率加权的策略上叠加 RP = 双重抑制

**正确做法**：
```python
# 低维（< 8 因子）: 不引入 RP
if n_factors < 8:
    weights = inverse_vol_weights   # 简单逆波动足够

# 高维（≥ 8 因子）: 考虑 LW + RP
else:
    Σ = ledoit_wolf_shrink(X.T @ X / n)  # Ledoit-Wolf 收缩
    weights = risk_parity_weights(Σ)     # RP
```

**防范流程**：
1. **引入协方差估计前**：先确认因子维度 ≥ 8
2. **小样本验证**：用 bootstrap 评估 Σ 估计稳定性
3. **RP 不是万灵药**：在已经使用逆波动率的策略上叠加是负增益

**关联**：[05_LESSONS_LIBRARY §L-132](../research_history/05_LESSONS_LIBRARY.md) LW 在低维（5 因子）下不显著优于 IC²

### L-20260708-2: shim 文件移除要彻底，caller 也要同步 [MEDIUM]

**问题**：M4.5 移除 `wiki.py` shim 后，必须更新所有 caller 使用新的子包导入路径。后续 M4.6 又做 caller-async 化，说明 shim 移除不是"删文件"那么简单。

**根因**：Python 的 import 灵活性导致 shim 可以"静默"地工作——旧代码 `from wiki import X` 通过 shim 仍然能找到 `X`。这种隐性依赖是技术债的温床。

**正确做法**：
```python
# 错误: 保留 shim "为了兼容性"
# wiki.py (shim):
from wiki.subpackage import *  # 重新导出

# 正确: 一次性彻底迁移
# 1. grep 所有 caller: `grep -r "from wiki" --include="*.py"`
# 2. 批量替换: `from wiki.subpackage import X` → `from wiki.subpackage.module import X`
# 3. 删除 shim
# 4. 测试确认
```

**防范流程**：
1. **shim 文件登记**：所有 shim 必须有 TODO 注释 + 移除日期
2. **移除流程**：先列 caller，再批量替换，最后删 shim
3. **移除后**：跑完整测试套件 + grep 二次确认无遗漏引用

**关联**：[05_LESSONS_LIBRARY §L-323](../research_history/05_LESSONS_LIBRARY.md) 工程债的"识别 + 修复 + 预防"
