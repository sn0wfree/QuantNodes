## 当日教训

### L-20260707-1: concentration caps 与逆波动率加权冲突 [MEDIUM]

**问题**：在 Stage 10 引入 concentration caps（限制单资产最大权重），实测 Calmar -22%（NO-GO）。

**根因**：v3 时期已经使用**逆波动率加权**（`weights ∝ 1/σ`），高波动品种自然降权。再加 concentration caps 反而是"双重抑制"——把已经分散的权重再强制收窄，导致：
- 优质高波动资产被错误降权
- 中等波动资产被强制提升（不是因为它们好）
- 整体风险/收益比被破坏

**正确做法**：
```python
# 逆波动率加权已隐式做分散，不需要再加 caps
σ = std(log_ret_60d) × √252
weights = (1 / σ).clip(upper=cap)  # 双重抑制 ❌
# vs.
weights = (1 / σ) / sum(1 / σ)     # 自然分散 ⭐
```

**防范流程**：
1. **加新约束前**：先量化现有约束的实际效果
2. **逆波动率 + caps**：是已知冲突组合（与 L-121 配合）
3. **任何"再保险"机制**：必须做 A/B 测试证明增益

**关联**：[05_LESSONS_LIBRARY §L-121](../research_history/05_LESSONS_LIBRARY.md) 逆波动率加权是稳健基线

### L-20260707-2: 交易成本模型是 P0 必备，不是 nice-to-have [HIGH]

**问题**：Stage 13 引入 transaction cost model。在没有成本模型之前，所有回测都是"无摩擦"状态。

**根因**：早期阶段为了快速迭代，回测代码用 `returns = weights.shift(1) * asset_returns`，无任何成本扣除。这导致：
- 高换手策略被严重高估
- 真实交易成本（佣金 + 印花税 + 滑点）无法反映
- OOS 表现与回测表现系统性偏差

**正确做法**：
```python
# 必须包含的最低成本模型
cost_bps = {
    'commission': 1.5,    # 佣金 万 1.5
    'stamp_tax': 5.0,     # 印花税 万 5 (仅卖出)
    'slippage': 2.0,      # 滑点 万 2 (保守估计)
}
turnover = (weights - weights.shift(1)).abs().sum(axis=1)
cost = turnover * (cost_bps['commission'] + cost_bps['slippage']) / 10000
nav = (1 + portfolio_ret - cost).cumprod()
```

**防范流程**：
1. **任何回测代码**：必须显式建模成本（即使粗略）
2. **成本参数**：用行业标准（万 1.5 佣金 + 万 5 印花税 + 万 2 滑点）
3. **高换手策略**：成本敏感性测试是 P0

**关联**：与 L-211（OHLCV 前复权）配合 — 数据正确 + 成本正确才有意义
