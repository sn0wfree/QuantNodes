# QuantNodes 可选依赖安装指南

> v3.0.0 (Stage 5.3) 引入的破坏性变更 — ``nanobot-ai`` 不再是强制依赖。

## 概述

QuantNodes 采用 **可选依赖（extras）** 设计：

| 安装命令 | 适用范围 | 体积 | 适用场景 |
|----------|----------|------|----------|
| `pip install quantnodes`           | 纯量化工具库 | ~30MB  | 写策略、回测、做因子研究；不跑 agent |
| `pip install 'quantnodes[agent]'`  | + nanobot agent | ~150MB | 需要 LLM 驱动的 agent / WebUI / 多 channel |
| `pip install 'quantnodes[mcp]'`    | + MCP server | ~50MB  | 想把 quant 工具通过 MCP 暴露给其他客户端 |
| `pip install 'quantnodes[all]'`    | agent + mcp | ~200MB | 一键装齐 |
| `pip install 'quantnodes[streamlit-ui]'` | Streamlit 实验 UI | ~80MB | 实验性 Streamlit 演示 |

`nanobot-ai` (HKUDS/nanobot 0.2.1) 现在是 **可选依赖**：
- 装了 → 完整 agent 体验（WebUI / WebSocket / cron / subagent / 多 channel）
- 没装 → 量化库功能（Wiki / Factor / Backtest / Strategy / DuckDB 等）完全可用，agent 相关 API 返回 503 + 友好的 install 提示

## 升级指南

### 旧用户（v2.x → v3.0.0）

旧版本（v2.8.x 及之前）的 `nanobot-ai` 是强制依赖。从 v3.0.0 起改为可选：

```bash
# 1. 升级主包
pip install --upgrade quantnodes

# 2. 显式装回 [agent] extras（agent 相关功能需要）
pip install 'quantnodes[agent]'

# 3. 验证
python -c "from QuantNodes.agent import NANOBOT_AVAILABLE; print('nanobot:', NANOBOT_AVAILABLE)"
# 应输出: nanobot: True
```

如果跳过第 2 步：
- 量化库（Wiki / Factor / Backtest / Strategy）继续正常工作
- AgentChat 路由显示安装提示页
- `GET /api/agent/status` 返回 `{available: false, hint: "pip install 'quantnodes[agent]'"}`
- `POST /api/agent/chat/send` 返回 503 + install hint

### CI / Docker

```dockerfile
# 推荐：分阶段安装
RUN pip install quantnodes              # 基础
RUN pip install 'quantnodes[agent]'    # agent 功能
# 或一行：
RUN pip install 'quantnodes[all]'
```

`pyproject.toml` 中 `nanobot-ai>=0.2.1,<0.3.0` 已移到 `[agent]` extras；`>=0.2.1,<0.3.0` 是 alpha 期的次版本锁，避免上游 0.3.x 的 API 破坏。

## 单进程架构（v3.0.0 新增）

v3.0.0 的 agent runtime 与 FastAPI 在 **同一 Python 进程** 内运行：

```
QuantNodes 进程（uvicorn 启动）
├─ FastAPI :8000          ← 量化 REST API
├─ nanobot :18080         ← WebUI SPA + WebSocket (同进程)
│   ├─ AgentLoop          ← asyncio.Task
│   ├─ ChannelManager     ← 启动 websocket server
│   ├─ CronService        ← asyncio.Task
│   └─ QuantDream hook    ← asyncio.Task
└─ MCP server (stdio)     ← 被 nanobot 拉起
```

启动时通过 `NANOBOT_GATEWAY_PORT`（默认 `18080`）配置：

```bash
# .env
NANOBOT_GATEWAY_HOST=127.0.0.1
NANOBOT_GATEWAY_PORT=18080
NANOBOT_WORKSPACE=.agent
```

前端 `Agent Chat` 入口 (`/agent-chat`) 默认指向 `http://127.0.0.1:18080/`，可通过 `VITE_NANOBOT_GATEWAY_URL` 覆盖。

## API 契约（agent 端点）

`/api/agent/*` 端点对所有用户（包括未装 `[agent]` extra 的）都返回 200 或 503 + 友好提示：

| 端点 | 装了 extras | 未装 extras |
|------|-------------|-------------|
| `GET /api/agent/status` | 200 + `{state: "running", components: {...}}` | 200 + `{state: "unavailable", hint: "pip install 'quantnodes[agent]'"}` |
| `GET /api/agent/health` | 200 (state=running) | 503 + hint |
| `POST /api/agent/restart` | 200 / 500 | 503 + hint |
| `POST /api/agent/chat/send` | 200 + response | 503 + hint |
| `GET /api/agent/sessions` | 200 + list | 503 + hint |
| `DELETE /api/agent/sessions/{key}` | 200 / 404 | 503 + hint |

前端 AgentChat.vue 会轮询 `/api/agent/status`：
- `state=unavailable` → 渲染 install 提示页
- `state=starting` → 渲染 loading
- `state=error` → 渲染错误 + 重试按钮
- `state=running` → 渲染 `<iframe src="...">` 嵌入 nanobot WebUI

## 常见问题

### Q: 升级后 `from QuantNodes.agent import Agent` 报错怎么办？

A: 这是 v3.0.0 的预期行为。`Agent` 类的属性访问会抛 `NanobotNotInstalled`：

```python
from QuantNodes.agent import NANOBOT_AVAILABLE, Agent

if not NANOBOT_AVAILABLE:
    print("nanobot-ai 没装。运行: pip install 'quantnodes[agent]'")
else:
    agent = Agent(workspace=".agent")
```

### Q: 不想用 agent 也能跑回测吗？

A: 可以。`pip install quantnodes` 即可，quant 库（backtest / factor / strategy / wiki）完全独立。

### Q: 启用了 [agent] extra 之后，WebUI 还是 404 怎么办？

A: 检查 nanobot SPA 是否构建。0.2.1 的 `nanobot/web/dist/` 目录是 hatch 构建产物。如果 `pip install` 后该目录为空：

1. 从 [github.com/HKUDS/nanobot](https://github.com/HKUDS/nanobot) clone 源码
2. `cd webui && npm install && npm run build`
3. 这会填充 `nanobot/web/dist/`
4. 重启 FastAPI

WebSocket API (`/api/sessions`, `/api/commands`) 不需要 SPA，可立即使用。

### Q: 端口 18080 被占用了怎么办？

A: 设置 `NANOBOT_GATEWAY_PORT=28080`（或其他），同时设置 `VITE_NANOBOT_GATEWAY_URL=http://127.0.0.1:28080/`（前端 env）。

### Q: 能不能让 nanobot 跑在独立的进程里？

A: 可以，绕过 `api/services/nanobot_runtime.py`，手动 `subprocess.Popen(['python', '-m', 'nanobot', 'gateway', '--port', '18080', '--workspace', '.agent'])`。但这会与"单进程"架构不兼容（用户需自行管理生命周期）。

## 开发 / 测试依赖（贡献者）

运行**全量**测试套件需要几个系统级 / 可选依赖。缺失时相关测试会**优雅降级或跳过**（不会让套件崩溃），但要 0 失败需全部装齐（Python 3.11）：

```bash
pip install ta-lib tables plotly
```

| 依赖 | 影响的测试 | 缺失时行为 |
|------|-----------|-----------|
| `ta-lib` | 66 个 talib 算子测试 | `talib_ops.py` 导入失败 → 测试 error；**需先装 TA-Lib C 库**（`apt install ta-lib` 或源码编译） |
| `tables`（PyTables） | HDF5 读写测试 | 相关测试 error |
| `plotly` | 可视化 / dashboard / e2e HTML 报告 | figure 函数返回 `None`、HTML 渲染降级为安装提示；纯 plotly 测试用 `pytest.importorskip` 跳过 |
| `sklearn` | TF-IDF 检索 | `TFIDFRetriever` 回退到 `IdentityRetriever`（`RuntimeWarning`） |
| `pymysql` | MySQL 集成测试 | 测试 skip |

> **注意**：`plotly` 缺失时 e2e 生成的 HTML 报告只含安装提示（~1.6KB），低于 e2e 测试的 5KB 校验阈值 → 该 e2e 测试会失败。装上 `plotly` 后报告含真实交互图（>5KB）。

期望基线（Python 3.11 + pandas 3.0，装齐上述依赖后）：

```
非 agent 测试: 5163 passed / 21 skipped / 0 failed / 0 errors（顺序 + 并行均通过）
tests/agent:   574 passed / 13 skipped
```

> 全量测试不要依赖测试执行顺序。历史上 8 个「单跑通过、全量失败」的测试均源于跨测试状态泄漏（`os.environ["HOME"]` 未还原、全局 composite registry 未清理），已在 v3.0.0 Stage 6 根因修复。新增测试请用 `monkeypatch.setenv` 而非裸 `os.environ[...] = ...`，并对全局注册表用快照/还原 autouse fixture。
