# QuantNodes 核心功能框架设计

> 本文档梳理 QuantNodes 系统的三大核心功能和实施路径。  
> 详细的数据加载设计见 `10-database与数据加载.md`，详细的设计见 `15-Config-Driven方案.md`。

---

## 一、系统定位

QuantNodes 是一个 **Agent 驱动的量化研究平台**，核心理念：

- Agent 理解用户需求，自动完成策略研发全流程
- 通过配置（YAML + conn.ini）驱动回测，无需手写代码
- 知识库持续积累，策略/因子/研报形成可复用的知识资产

---

## 二、三大核心功能

### 功能1: Agent 驱动的策略回测

**用户场景**: "帮我写一个双均线策略，回测一下看看效果"

**完整链路**:

```
用户需求 → Agent 理解需求
  ├── 搜索 Wiki: 是否已有类似策略/因子?        ← LLMWikiFy
  ├── 读取数据: ClickHouse / CSV / Parquet     ← database_node + config
  ├── 生成策略: YAML 配置                       ← ConfigBacktestTool
  ├── 执行回测: ConfigBacktestRunner            ← 回测引擎
  ├── 生成报告: Markdown 分析报告               ← LLMWikiFy
  └── 保存 Wiki: 策略页面 + 回测结果            ← LLMWikiFy
```

**缺口**: 数据层断裂（database_node 未接入 config 管线）— executor/runner 硬编码列名已修复（见 `19-基础设施修复与工具实现.md`）

### 功能2: 策略监控与优化

**用户场景**: "监控这个策略的样本外表现，如果跑偏了就优化"

**缺口**: 调度层空白、监控层空白、版本管理层空白

### 功能3: 研报复现

**用户场景**: "找一篇量化研报，把里面的因子复现出来，回测一下"

**缺口**: PDF 解析集成、因子自动提取、因子库管理

```
┌─────────────────────────────────────────────────────────┐

├─────────────────────────────────────────────────────────┤

│  Layer 1: 处理节点                                        │
│  节点层 + 数据层                                          │

```

## 四、关键依赖

### 已有依赖

| 组件 | 位置 | 能力 |
|------|------|------|
| `ClickHouseNode` | `database_node/` | HTTP + Native 双接口 |
| `CSVNode` / `ParquetNode` | `database_node/` | 文件读取 |
| `IniConfigNode` | `conf_node/` | INI 配置解析 |
| `factor_functions` (317个) | `factor_node/` | 算子库（含174个TA-Lib指标） |
| `ConfigExecutor` | `agent/config/` | YAML→Polars 计算 |
| `ConfigBacktestRunner` | `backtest/` | 回测执行 |
| `RiskNode` 系列 | `backtest/` | 风控 |
| `ExecutionBrokerNode` | `backtest/` | 撮合 |

### 外部依赖

| 组件 | 能力 |
|------|------|
| LLMWikiFy | PDF 解析、Wiki 管理、知识图谱、MCP Server |

## 五、实施路径

### Phase 1: 打通回测链路 (功能1)

1. 修复阻塞性 Bug（executor/runner 硬编码）
2. 扩展 DataConfig（新增 table, conn_ini, column_mapping 字段）
3. 接入 ClickHouse（`_load_data()` 分发到 `ClickHouseNode`）
4. 创建 `conn.ini`

### Phase 2: 监控与优化 (功能2)

1. 调度层
2. 监控层
3. 版本层

### Phase 3: 研报复现 (功能3)

1. PDF 解析集成
2. 因子提取定制
3. 因子库管理

---

## 六、设计原则

1. **配置驱动**: 用户只需写 YAML + conn.ini，不改代码
2. **复用优先**: 优先复用 database_node、factor_node、LLMWikiFy
3. **渐进增强**: 先打通核心链路，再逐步增强
4. **知识积累**: 所有策略/因子/研报都沉淀到 Wiki
