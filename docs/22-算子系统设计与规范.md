## 一、系统架构概览

QuantNodes 的算子系统由三层组成：

| 层级 | 文件 | 职责 |
|------|------|------|
| 入口层 | `operators/proxy.py` | 统一入口，re-export 注册表 API |
| 注册层 | `factor_node/factor_functions/__init__.py` | 公开 API，装饰器注册表 |
| 实现层 | `factor_node/factor_functions/{time,section,math,composite,talib}_ops.py` | 纯 Polars 算子实现 |

当前注册算子总计 **317 个**（point: 46, time: 65, section: 17, multi_section: 15, talib: 174）。

旧系统（`factor_nodes.py`、`factor_operation.py` 中的 DerivativeFactor）已废弃或仅保留内部执行引擎。

## 二、命名约定

### 2.1 总体规则

- **全部使用 snake_case**，禁止 camelCase
- 已有的 camelCase 算子（如 `standardizeZScore`）添加 snake_case 别名
- 名称必须清晰表达语义

### 2.2 前缀规则

| 前缀 | 分类 | 示例 |
|------|------|------|
| `rolling_` | time | `rolling_mean`, `rolling_std`, `rolling_quantile` |
| `expanding_` | time | `expanding_sum`, `expanding_max` |
| `ewm_` | time | `ewm_mean`, `ewm_std`, `ewm_corr` |
| `ts_` | time（别名前缀） | `ts_mean` (= `rolling_mean`), `ts_delta` |
| `decay_` | time | `decay_linear`, `decay_exp` |
| `group_` | section | `group_norm`, `group_winsorize` |
| `aggr_` | multi_section | `aggr_sum`, `aggr_mean` |
| `talib_` | talib (TA-Lib) | `talib_rsi`, `talib_sma`, `talib_macd_line` |
| `custom_` | custom（用户自定义） | `custom_momentum_zscore` |
| 无前缀 | point / section | `abs`, `log`, `rank`, `zscore` |

### 2.3 禁止事项

- 禁止单字母变量名作为算子名（`f`、`x` 除外，它们是参数名）
- 禁止缩写（如 `avg` 应写为 `average` 或使用已有 `mean`）
- 禁止与 Polars 内置方法完全同名的算子名（如 `shift`、`diff`）

## 三、签名约定

### 3.1 标准签名模板

```python
@register_operator(OperatorCategory.TIME)
def rolling_mean(
    f: Union[Expr, str],           # 首参：输入表达式或列名
    window: int = 20,              # 领域参数，带默认值
    min_periods: Optional[int] = None,
    **kwargs                        # 末参：必须，吸收 YAML 未知参数
) -> Expr:                          # 返回：polars.Expr
    """滚动窗口均值"""
    return TimeSeriesOperators.ts_mean(f, window, min_periods)
```

### 3.2 签名规则

| 规则 | 说明 |
|------|------|
| **首参** | `f`（单输入）或 `f1, f2`（双输入），类型 `Union[Expr, str]` |
| **末参** | `**kwargs` 必须存在，吸收 YAML `params` 中的未知参数 |
| **返回类型** | `polars.Expr` |
| **类型注解** | 所有参数必须有类型注解 |
| **默认值** | 所有非首参参数必须有默认值 |

### 3.3 operators/ 实现层签名

```python
@staticmethod
def ts_mean(
    expr: Union[Expr, str],
    window: int = 20,
    min_periods: Optional[int] = None
) -> Expr:
    if isinstance(expr, str):
        expr = pl.col(expr)
    # ... 实现
```

实现层**不接受** `**kwargs`，参数更严格。

### 3.4 双输入算子签名

```python
@register_operator(OperatorCategory.TIME)
def rolling_corr(
    f1: Union[Expr, str],
    f2: Union[Expr, str],
    window: int = 20,
    min_periods: Optional[int] = None,
    **kwargs
) -> Expr:
    """滚动相关系数"""
    return TimeSeriesOperators.ts_corr(f1, f2, window, min_periods)
```

## 五、分类规则

### 5.1 五个分类

| 分类 | registry category | executor type | 语义 | 数量 |
|------|-------------------|---------------|------|------|
| **point** | `point` | `math` | 行级数学运算，无时间/截面上下文 | 46 |
| **time** | `time` | `time_series` | 时间序列操作（滚动/扩张/EWM/偏移） | 65 |
| **section** | `section` | `section` | 截面操作（单时间点内 rank/zscore/winsorize） | 17 |
| **multi_section** | `multi_section` | `composite` | 分组聚合（group_by + agg） | 15 |
| **talib** | `talib` | `talib` | TA-Lib 技术分析指标 | 174 |

### 5.2 分类判断流程

```
算子需要什么上下文？
├── 无上下文，逐行计算 → point (math)
├── 需要历史数据窗口 → time (time_series)
│   ├── 固定窗口 → rolling_*
│   ├── 累积窗口 → expanding_*
│   ├── 指数加权 → ewm_*
│   └── 偏移/差分 → ts_delta, ts_lag, ts_pct_change
├── 需要同一时间点的其他标的 → section
│   ├── 全截面 → rank, zscore, winsorize
│   └── 分组内 → group_norm, group_winsorize
├── 需要分组聚合 → multi_section (composite)
│   ├── 聚合计算 → aggr_sum, aggr_mean
│   └── 多列组合 → weighted_sum, combine
└── 技术分析指标 → talib
    └── TA-Lib 包装 → talib_rsi, talib_sma, talib_macd_line
```

### 5.3 分类冲突处理

当一个算子同时涉及时间和截面时：
- **时间优先**：如 `ts_rank`（滚动窗口内 rank），分类为 `time`
- **截面优先**：如 `group_norm`（分组内 zscore），分类为 `section`

## 六、注册流程

### 6.1 完整注册清单

添加一个新算子的标准步骤：

**Step 1: 在 `operators/` 添加实现**

```python
# operators/time_series.py
@staticmethod
def my_new_op(
    expr: Union[Expr, str],
    window: int = 20,
    min_periods: Optional[int] = None
) -> Expr:
    """新算子说明"""
    if isinstance(expr, str):
        expr = pl.col(expr)
    # ... Polars 实现
```

**Step 2: 在 `factor_functions/time_ops.py` 注册**

```python
@register_operator(OperatorCategory.TIME)
def my_new_op(
    f: Union[Expr, str],
    window: int = 20,
    min_periods: Optional[int] = None,
    **kwargs
) -> Expr:
    """新算子说明"""
    from QuantNodes.operators import TimeSeriesOperators
    return TimeSeriesOperators.my_new_op(f, window, min_periods)
```

**Step 3: 加入 `__all__`**

```python
# factor_functions/time_ops.py 末尾
__all__ = [
    ...,
    "my_new_op",
]
```

**Step 4: 在 `operators/__init__.py` 导出**

```python
# operators/__init__.py
from .time_series import TimeSeriesOperators
__all__ = [..., "my_new_op"]
```

仅当需要优化性能或有特殊参数映射时才需要。大多数情况下 registry fallback 已足够。

### 6.2 注册后验证

```python
# 验证注册成功
from QuantNodes.factor_node.factor_functions import get_operator, list_operators
assert "my_new_op" in [op["name"] for op in list_operators()]
assert get_operator("my_new_op") is not None
```

## 七、算子扩展机制

### 7.1 背景

ConfigExecutor 的 OperationConfig dispatch 硬编码了部分算子，但 registry 有 317 个。用户可能需要使用 registry 中未硬编码的算子，或定义全新的自定义算子。

### 7.2 架构

```
ConfigExecutor._apply_operator(op)
  │
  ├── 硬编码 dispatch（优先）
  │     ├── _apply_ts_operator(category, input_exprs, params)
  │     ├── _apply_sec_operator(category, input_exprs, params)
  │     ├── _apply_math_operator(category, input_exprs, params)
  │     ├── _apply_composite_operator(category, input_exprs, params)
  │     └── _apply_talib_operator(category, input_exprs, params)
  │
  ├── fallback: get_operator() 从 registry 查找
  │     └── op_func(*input_exprs, **params)
  │
  └── 最终兜底: return input_exprs[0]
```

### 7.3 通用 Fallback

在 `_apply_operator()` 的硬编码 dispatch 之后，增加 fallback：

```python
def _apply_operator(self, op):
    # ... 现有硬编码分支（如果匹配则 return）...

    # fallback: 从 registry 查找
    try:
        from QuantNodes.factor_node.factor_functions import get_operator
        op_func = get_operator(category)
        if op_func is not None:
            return op_func(*input_exprs, **params)
    except Exception:
        pass

    return input_exprs[0]
```

**效果**：`rolling_quantile`、`regress`、`decay_linear` 等未硬编码的 registry 算子可通过 OperationConfig 直接使用。

### 7.4 优先级规则

1. **硬编码 dispatch 最高**：如果 category 匹配 if/elif 分支，直接返回
2. **Fallback 次之**：从 registry 查找，覆盖 317 个已有算子
3. **Custom 算子**：通过 `register_operator()` 注册到 registry，被 fallback 发现
4. **最终兜底**：返回 `input_exprs[0]`

## 八、自定义算子加载

### 8.1 YAML 配置格式

```yaml
# 简单格式（向后兼容，默认分类 point）
validation:
  custom_operators:
    - "/absolute/path/to/my_ops.py"

# 详细格式（推荐，显式指定分类）
validation:
  custom_operators:
    - source: "/absolute/path/to/my_ops.py"
      category: "time_series"
      functions: ["custom_momentum_zscore"]  # 可选，不填则自动发现 custom_* 函数
```

### 8.2 自定义算子文件格式

```python
# /path/to/my_custom_ops.py
import polars as pl

def custom_momentum_zscore(f, window=20, zscore_window=60, **kwargs):
    """自定义动量 Z-Score"""
    momentum = f / f.shift(window) - 1
    return (momentum - momentum.rolling_mean(zscore_window)) / momentum.rolling_std(zscore_window)

def custom_decay_linear(f, window=10, **kwargs):
    """自定义线性衰减"""
    weights = list(range(1, window + 1))
    total = sum(weights)
    return f.rolling_mean(window) * (window / total)
```

### 8.3 加载流程

```python
def _load_custom_operators(self, custom_operators):
    """加载自定义算子"""
    for entry in custom_operators:
        # 解析配置（支持 str 和 dict 两种格式）
        if isinstance(entry, str):
            source_path = entry
            category = "point"
            functions = None
        else:
            source_path = entry["source"]
            category = entry.get("category", "point")
            functions = entry.get("functions")

        # importlib 动态加载
        spec = importlib.util.spec_from_file_location("custom_ops", source_path)
        module = importlib.util.module_from_spec(spec)
        spec.loader.exec_module(module)

        # 注册算子
        for name in dir(module):
            if name.startswith("_"):
                continue
            if functions and name not in functions:
                continue
            if not functions and not name.startswith("custom_"):
                continue

            func = getattr(module, name)
            if callable(func):
                register_operator(category, name=name)(func)
```

### 8.4 分类映射

| YAML category | executor dispatch | registry 分类 |
|---------------|-------------------|---------------|
| `time_series` | `_apply_ts_operator` | `time` |
| `section` | `_apply_sec_operator` | `section` |
| `math` | `_apply_math_operator` | `point` |
| `composite` | `_apply_composite_operator` | `point` / `multi_section` |
| `talib` | `_apply_talib_operator` | `talib` |

Custom 算子注册到 `_OPERATOR_REGISTRY["custom"]`，fallback 通过名称全局查找。

### 8.5 程序化自定义算子 API（Feature 3D）

除 YAML 加载外，QuantNodes 还提供程序化方式定义自定义算子：

```python
from QuantNodes.operators import CustomOperator

# 装饰器风格（直接注册）
@CustomOperator.point("my_double")
def my_double(f, multiplier=2.0):
    return f * multiplier

# Builder 链式风格
my_ewm_30 = (CustomOperator.time("my_ewm_30")
    .param("span", int, 30, "窗口大小")
    .execute(lambda s, span: s.ewm_mean(span=span))
    .register())

# 截面算子
@CustomOperator.section("my_zscore")
def my_zscore(s):
    return (s - s.mean()) / s.std()

# 模板工厂（基于内置算子）
my_ewm_30 = CustomOperator.time_from("my_ewm_30", "ewm_mean", span=30)
```

级联查询：`get_operator()` 先查自定义注册表，再查内置注册表。

详见 [Feature 3D 设计文档](Feature3D-用户友好自定义算子API设计.md)。

## 九、YAML 配置规范

### 9.1 operations 块写法

```yaml
operations:
  - type: time_series          # 分类（对应 executor dispatch）
    name: momentum_ma          # 输出列名
    category: ts_mean          # 算子名（必须在 registry 中存在）
    inputs: [returns_20d]      # 输入列/因子名列表
    params:                    # 参数字典（映射到函数 kwargs）
      window: 20
```

### 9.2 type 与 registry category 对应表

| YAML type | executor dispatch | registry category |
|-----------|-------------------|-------------------|
| `time_series` | `_apply_ts_operator` | `time` |
| `section` | `_apply_sec_operator` | `section` |
| `math` | `_apply_math_operator` | `point` |
| `composite` | `_apply_composite_operator` | `point` / `multi_section` |
| `talib` | `_apply_talib_operator` | `talib` |

### 9.3 params 映射规则

YAML `params` 字典的 key 必须与算子函数参数名**完全一致**：

```yaml
params:
  window: 20        # → rolling_mean(f, window=20)
  alpha: 0.5        # → ewm_mean(f, alpha=0.5)
  lower: 0.01       # → winsorize(f, lower=0.01)
```

拼写错误会被 `**kwargs` 静默吸收，不会报错但算子会使用默认值。

## 十三、TA-Lib 技术分析集成

### 13.1 概述

QuantNodes 通过 `operators/talib.py` 集成了 TA-Lib 0.6.x（174 个技术分析指标），覆盖：
- **重叠/趋势** (17): SMA, EMA, DEMA, TEMA, WMA, KAMA, T3, BBANDS, MA, ...
- **动量** (30): RSI, MACD, STOCH, CCI, WILLR, MFI, ROC, MOM, ADX, ...
- **波动率** (3): ATR, NATR, TRANGE
- **成交量** (3): AD, ADOSC, OBV
- **K线形态** (61): CDL_DOJI, CDL_HAMMER, CDL_ENGULFING, ...
- **统计函数** (9): BETA, CORREL, LINEARREG, STDDEV, ...

### 13.2 安装

```bash
pip install TA-Lib          # 0.6.5+ 自带 C 库 binary wheel (x86_64 Linux)
pip install quantnodes[talib]  # 通过 extras 安装
```

### 13.3 YAML 配置示例

```yaml
operations:
  - type: talib
    name: rsi_14
    category: talib_rsi
    inputs: [close]
    params: {timeperiod: 14}

  - type: talib
    name: sma_20
    category: talib_sma
    inputs: [close]
    params: {timeperiod: 20}

  - type: talib
    name: bb_upper
    category: talib_bbands_upper
    inputs: [close]
    params: {timeperiod: 20, nbdevup: 2.0}
```

### 13.4 命名约定

所有 TA-Lib 算子使用 `talib_` 前缀：
- 单输出: `talib_rsi`, `talib_sma`, `talib_atr`
- 多输出拆分: `talib_macd_line`, `talib_macd_signal`, `talib_macd_hist`
- 布林带拆分: `talib_bbands_upper`, `talib_bbands_middle`, `talib_bbands_lower`

### 13.5 实现机制

TA-Lib 函数通过 `map_batches` 桥接 Polars ↔ NumPy：
```python
@staticmethod
def rsi(expr, timeperiod=14):
    import talib
    e = _ensure_expr(expr)
    return e.map_batches(
        lambda s: pl.Series(talib.RSI(s.to_numpy(), timeperiod=timeperiod)),
        return_dtype=pl.Float64,
    )
```

K线形态识别函数返回 `Int32`（-100, 0, 100），使用 `return_dtype=pl.Int32`。

### 16.1 问题描述（已修复）

> 以下描述的是重构前的旧架构问题，该问题已通过本计划实施解决。

当前架构存在两套独立系统：

```
operators/ (静态类，无注册)
    └── TimeSeriesOperators.ts_mean() ← 独立函数，无注册

factor_node/factor_functions/ (@register_operator 注册表)
    └── rolling_mean() → 委托 operators/

agent/config/executor.py, loader.py

```

**问题**：
1. 两套独立系统，用户困惑
2. `factor_functions/` 80% 是薄代理，无增值
3. 单一文件 2500+ 行，难以维护

### 16.2 目标架构

```
operators/ (唯一入口，门面层)
├── __init__.py (re-export 注册表API)
├── proxy.py (统一管理 re-export)
├── time_series.py → 代理 factor_functions.time_ops
├── section.py → 代理 factor_functions.section_ops
└── talib.py → 代理 factor_functions.talib_ops

factor_functions/ (实现层)
├── __init__.py (注册表、register_operator)
├── time_ops.py (时间序列算子实现)
├── section_ops.py (截面算子实现)
├── math_ops.py (数学算子实现)
├── composite_ops.py (组合算子实现)
└── talib_ops.py (TA-Lib 包装)
```

### 16.3 关键原则

1. `operators/` 是**唯一入口**，对外接口不变
2. `factor_functions/` 是**实现层**，只被 `operators/` 调用
3. `agent/` 系统改从 `operators/` 导入，不直接依赖 `factor_functions/`

### 16.5 技术债务清理

#### rank_sort 与 ConfigExecutor 兼容性问题（已修复）

**问题**: `test_rank_sort` 测试失败，`'list' object has no attribute 'alias'`

**原因**: `CompositeOperators.rank_sort()` 返回 `List[Expr]`，但 `executor._apply_operator()` 期望单个 `Expr`

**解决方案**:
1. 修改 `executor.run()` 方法：检测 `List[Expr]` 返回值，使用双下划线后缀拆分存储（如 `c_rs__0`, `c_rs__1`）
2. 修改 `executor._execute_plan()` 方法：检测 `__` 模式，使用原始 operation name 作为列别名

**关键改动**: 使用双下划线 `__` 而非单下划线 `_` 避免与 TA-Lib 名称冲突（如 `rsi_14`）

## 十七、Composite DAG 算子 (PR-QN-3a/b, 2026-06-21)

### 17.1 背景

现有算子层 (一~七章) 是**基础 polars primitive** (Level 0) 与**业务语义算子** (Level 1), 缺少中间的 **DAG 模板复合**层. llmwikify Loop v4 等下游系统需要"参数化 + 嵌套 + 文档自描述"的复合算子 — 例如 `industry_neutralize` 不是单 op, 而是 `x - x.group_by(industry_col).mean()` 这样一个**带参模板**.

PR-QN-3a 提供核心抽象 (ParamSpec / CompositeSpec / 装饰器 / 注册表 / YAML 扩展), PR-QN-3b 注入 20 个内置 op. 整体设计与 `multi_section` (Level 0 现存层) **共存**而非替代.

### 17.2 4 层抽象

| 层 | 归属 | 例子 |
|---|---|---|
| L0 Primitive | QuantNodes | `rolling_mean`, `zscore`, `add` |
| L1 Composite DAG | **PR-QN-3 新增** | `industry_neutralize`, `pair_zscore`, `garman_klass_vol` |
| L2 Polars Native | llmwikify 自建 | `pl.when(...).then(...).otherwise(...)` |
| L3 Semantic | llmwikify 自建 | 业务语义 |

### 17.3 核心 API (PR-QN-3a)

```python
from QuantNodes.operators import (
    composite_operator, CompositeSpec, ParamSpec,
    is_composite_op, get_composite_spec, list_composite_ops,
    get_composite_doc_for_llm, load_composites_from_yaml,
)
from polars import Expr, col

# 用户定义
@composite_operator(
    name="my_neutralize",
    params={"x": {"type": "expr", "required": True},
            "industry_col": {"type": "str", "default": "citic_1"}},
    doc="行业中性化",
)
def my_neutralize(x: Expr, industry_col: str = "citic_1") -> Expr:
    return x - x.group_by(industry_col).mean()

# 查询
spec = get_composite_spec("my_neutralize")
result_expr = spec.instantiate(x=col("close"), industry_col="citic_1")
is_composite_op("my_neutralize")  # True
list_composite_ops()              # 20 个内置 + 用户自定义
```

### 17.4 设计要点

- **隔离注册表**: `_COMPOSITE_REGISTRY` 与现有 `_CustomOperatorRegistry` 平级, 不污染 L0.
- **`is_composite=True` 标记位**: composite 同时注入 `_OPERATOR_REGISTRY[category][name]`, 供统一 `get_operator()` 查询.
- **类型校验**: `ParamSpec.validate` 在 `instantiate` 时运行, 防运行时错误.
- **LLM 文档**: `get_composite_doc_for_llm()` 输出 markdown, 供 LLM prompt 使用.
- **YAML 扩展**: `load_composites_from_yaml()` 支持用户自定义 (用 ast 解析, 避免裸 exec).

### 17.4.1 Visitor pattern 扩展 (2026-06 增量)

> **详见**: [`docs/26-设计模式重构与审计.md` §1.1 Phase 1.5](../26-设计模式重构与审计.md)

`composite_dag.py` 新增 3 个 Visitor 子类，统一遍历 `_COMPOSITE_REGISTRY`:

| Visitor | 用途 |
|---|---|
| `LLMDocVisitor` | 生成 LLM prompt markdown (替代 `get_composite_doc_for_llm` 内联实现) |
| `DependencyVisitor` | 提取 composite 依赖图 + `detect_cycles()` |
| `ValidationVisitor` | required+default 冲突 / 空 doc / 缺 examples 等语义校验 |

未来新增 spec 遍历能力 (DAG 可视化、LLM 依赖注入、lint) 只需新增 Visitor 子类,
无需修改 `CompositeSpec` 本身。

### 17.5 与现有 `multi_section` 关系

| 维度 | `multi_section` | `composite_dag` |
|------|----------------|-----------------|
| 偏重 | 多数据源合并 | primitive DAG 模板 |
| 数量 | 15 | 20 (新增) |
| 标记 | 无 | `is_composite=True` |
| 装饰器 | 直接注册 | `@composite_operator` |

两者**完全共存**, 通过 `is_composite_op(name)` 区分. 用户代码不受影响.

### 17.6 20 个内置 op (PR-QN-3b, 2026-06-21)

按 `QuantNodes/operators/composite_dag_ops.py` 实现, 覆盖 quant 研究常见算法:

- **中性化 (3)**: `industry_neutralize` / `market_neutralize` / `subindustry_neutralize`
- **横截面归一化 (3)**: `zscore_xs` / `rank_xs` / `scale_xs`
- **滚动回归 (3)**: `rolling_beta` / `rolling_ols_simplified` / `rolling_residual`
- **波动率 (4)**: `parkinson_vol` / `garman_klass_vol` / `yang_zhang_vol` / `realized_vol`
- **配对交易 (2)**: `pair_zscore` / `pair_ratio`
- **缩尾/异常 (3)**: `winsorize` / `mad_outlier` / `zscore_clip`
- **复合时序 (2)**: `decay_linear_xs` / `momentum_accel`

#### 17.6.1 polars 1.40 适配调整

PR-QN-3a 规划阶段文档原版基于假想的 polars 0.x API. 经实测 polars 1.40.1, 实际 API 调整如下:

| op | 文档原版 (不工作) | PR-QN-3b 实现 |
|---|---|---|
| 中性化 | `x - x.group_by(c).mean()` | `x - x.mean().over(c)` |
| `winsorize` | `x.clip(x.quantile(lq), x.quantile(uq))` | `x.clip(x.quantile(lq).over(), x.quantile(uq).over())` |
| `mad_outlier` | `x.where((x - median).abs() <= n_mad * mad)` | 用 `abs()` + `over()` 分组, 或全局版本 |
| `garman_klass_vol` | 公式错误 (log_hl² / 4log2) | 经典 GK 公式 0.5·log_hl² - (2ln2)·log_co² |
| `yang_zhang_vol` | 简化为 `log_hl.rolling_std` | 经典 YZ 公式 (overnight + open-to-close + Rogers-Satchell) |

详见 `composite_dag_ops.py` 注释.
